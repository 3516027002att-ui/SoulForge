# 反 AI 设计规范（硬约束）

本文件是后续实现与审查的硬约束。审查依据 ux-audit（L1+L2）与 frontend-design-review（Mode 1）。

## 1 禁止的默认视觉套路

除非有明确产品原因，否则禁止：紫蓝渐变；橙色发光科技皮肤与大面积 glow；玻璃拟态与装饰光斑；全元素圆角与超大圆角卡片；胶囊式文件标签与普通按钮；卡片套卡片；每区块图标+标题+副标题三件套；Hero 式居中布局；无意义线稿插图；为科技感的六边形；过度柔和阴影；所有状态彩色圆点；渐变边框；等宽字体覆盖所有技术词（等宽仅用于文件名/ID/路径/代码/数值）；极端但不适合工具的风格。

当前界面违规清单（基线截图）：欢迎页五节点数字圆圈流程卡（baseline-01）；标题栏 slogan tag"魂游 Mod 工作台"；Agent 模型标签"gpt-5.2 · 证据驱动"编造具体性；主按钮大面积橙填充且文案暴露内部引擎名；tab 激活文件名着橙。

## 2 禁止的 AI 文案套路

禁止：无证据形容词（智能/高效/安全/无缝/强大/革命性）；名词串联与"A · B · C"宣传摘要；为真实状态编造概念名；实现细节伪装成用户功能；每标题下一句模糊说明；"继续工作/探索更多/开始体验"泛化标题；过度中英混搭；欢迎语与 Agent 自我介绍长期占据主区域；"告诉我修改目标，我会……"式聊天默认介绍。

文案优先描述：当前对象、当前状态、已发生动作、下一步动作、影响范围、是否可逆、失败原因、恢复方式。

用户语言映射（内部名 → 主界面用语）：typed mutation/PatchIR → 变更；Patch Engine 提交 → 写入补丁（详情行保留内部名）；三层恢复 → 可回滚/回滚到此版本；原生解析 → 已解析 N 条 / 解析失败（原因）。

## 3 禁止的结构套路

禁止：Agent 以普通聊天软件形态为主体；五步流程图代替真实状态；所有流程阶段同时高亮；把不存在的数据画成完整状态；为填满页面制造功能卡；数字圆圈表现非教程流程；右侧 Agent 面板抢夺中央主视觉；主要编辑区变背景板；靠不断加边框和容器解决层级。

## 4 状态优先于概念

主界面必须能回答：已解析多少资源；当前文件/选中记录是什么；已生成多少变更；原值与新值；哪些差异待审查；是否已批准；是否已备份；写入是否成功；是否可回滚；失败原因；下一步可做什么。

## 5 审查测试（每轮必做，L2 截图证据）

Swap Test（换任意 AI IDE logo 是否仍成立）；Squint Test（主工作区是否最突出、Agent 是否过重、危险操作是否区分）；Grayscale Test（去色后层级与状态是否仍可识别）；Copy Test（隐藏图标颜色仅看文字能否理解状态与动作）；Density Test（高频操作是否易找、低频详情是否可折叠）。
