崩溃码 `0xC0000005` = 访问冲突（Access Violation，空/野指针），地址落在游戏主模块里。两个触发点：

- **接触道具/掉落** → 走 `ItemLotParam`（掉落表）+ `ItemLotParam_enemy` / `ItemLotParam_map`（敌人/地图掉落）

这两类表都是**索引式的引用表**：它们通过 ID 引用 `EquipParamGoods`（道具）等实体表。崩溃几乎都来自**引用了不存在的行 / 行结构错位**。

### 最可能的原因（按概率排序）

1. **掉落/商品引用了已删行或不存在 ID**
   在你编辑 `EquipParamGoods.param` 时，如果删掉或改动了某些 Goods ID，但 `ItemLotParam` / `ShopLineupParam` 里仍引用旧 ID，游戏读取时拿到空指针 → 直接崩溃，且只在「碰到/打开」时才炸。

2. **`EquipParamGoods.param` 单文件被拆出后行数/偏移错位**
   注意工作区里 `gameparam.parambnd.dcx`(985,910B) 和其 `.bak`(1,041,634B) **大小不一致**，说明打包后的 gameparam 比原始备份小了约 55KB。如果你编辑的 `EquipParamGoods.param` 是从旧版本拆出的、行字节数（每行宽度）与包内当前 PARAM 的行宽不匹配，整张表偏移错位 → 所有道具行数据全乱 → 接触任何道具即崩。

3. **商店/掉落修改未同步**：如果最近动过 `ShopLineupParam` 或 `ItemLotParam`，但没重打包 `gameparam.parambnd.dcx`，或改了 Goods 名/ID 后没回填引用，同样触发。
