# Decisions

## Owner decisions on 2026-10-04

The owner permits CI checks lacking required private game resources to remain explicitly unavailable/not_run without blocking the refactor merge. This permission does not waive actual failures, unknown skips, platform coverage or missing installer A/B configuration. Unit and E2E requirements remain; matching-source platform case reports must show an actual counterpart execution. Coverage limits and skipped cases remain visible and do not become verified passes.

Desktop Agent sessions default to bounded steps and total time without a monetary ceiling. The main-owned defaults are 200 steps and 180 seconds; trusted explicit monetary limits still apply. CLI/evaluator defaults are unchanged. Issue #54 remains deferred, and the independent mimo/reg-rebuild branches remain outside this task.

## Governance replacement

[Issue #49](https://github.com/3516027002att-ui/SoulForge/issues/49) supersedes the former line-budget and blanket-no-new-check premises in #22/#38/#39. Necessary product constraints stay at their actual execution boundaries. A scoped regression needs a scoped negative test, not a whole-repository claim/seal/freshness ceremony.

GitHub Issues describe work; CI records actual execution; this document records owner decisions; ARCHITECTURE.md and AGENTS.md expose stable boundaries and entry points. `check` discovers convention files and workspace aliases. Registration/audit findings remain reportable but cannot stop all independently parsed checks. Each actual failure, unavailable leg and not-run dependency remains visible.

The obsolete gov claim/heartbeat/release/complete/seal authority, scope/deferral/freeze projections, handoff integrity checks, required-validation registry and manual tier table are retired with their dedicated JSON and command aliases. `check` discovers the checks that exist; it needs no retired-suite blacklist. The historical handoff and [evidence ledger](historical-governance-evidence.jsonl) remain background records without executable freshness authority. Existing user artifacts are not implicitly authorized for deletion.

The remaining SF-29 historical acceptance-map/count/doc prerequisite and duplicate suite-delegation loop are retired. Its domain suites remain independently discovered, and its real Playwright entry assertion lives in the existing retirement fixture. The old `check-verify-summary` required-suite artifact wrapper is also retired; actual current-runner process tests retain passed, failed, unavailable and not_run evidence. Historical Flash plans, reports and receipts remain background records, without authority to declare current execution complete.

Root test forwarders without current consumers are removed where workspace discovery preserves the same execution operations. Active aggregates, called aliases and direct product checks remain. Root alias coverage is no longer audited as a registration requirement; actual execution determines each result. CI gives unrecognized JSON changes the ordinary product route, including files at the retired governance path.

Mission1's A0/A1/hourly framework is also retired: dirty-worktree approval, source/runner/summary hash quads, fixed assertion counts and all-FAIL product placeholders do not gate scoped work. The independent `generate-mission1-corpus-v2.mjs` / `verify-mission1-corpus-v2.mjs` tools and their existing corpus/output evidence remain available for their concrete input checks: filesystem size/content hashes, independently parsed artifacts, logical identity joins and disputed-result checks. The actual diff check, typecheck, Bridge/desktop builds and desktop IPC checks remain ordinary commands. No corpus or runtime pass is inferred from retiring the framework.

## Agent and native editing

[Issue #29](https://github.com/3516027002att-ui/SoulForge/issues/29) requires an independent control boundary while preserving native domain capability and Patch Engine authority. The finite kernel is independent, shared assembly serves desktop/CLI, and desktop control runs in a utilityProcess. Native read proofs are automatic host evidence, not model-authored proof labels or a mutation budget ledger.

Actual transaction results remain in the existing operation/journal system. Request cancellation, worker exit or transport loss does not imply not_committed. Unknown outcomes are queried rather than replayed.

Production desktop and CLI now share the finite Agent after the approved eight owned native comparisons. The old baseline `217234bb97ee20e3a83048042c4a1e67e9a16d33` remains only in explicit fixture-owned experiments. Real-provider quality and cost remain unverified within the owner-defined provider/task/budget/outcome experiment; this is a local comparison limit, not a startup gate. No fixed task count or universal format oracle becomes a new prerequisite for scoped work.

## Platform and scope

Windows and Linux are both product delivery targets, as explicitly confirmed by the user on 2026-09-30. Shared domain and Agent implementations use thin platform adapters. Builds, actual runtime, native ABI, resource support and packaging evidence are reported separately for each platform; portable tests do not establish Windows execution or GPU/image parity. Unsupported format/runtime behavior remains explicit. Unspecified owner choices and unconfirmed user-data cleanup are local blockers, not reasons to stop unrelated scoped work.

## 2026-09-30: oversized containers use optional read-only unpack transport (#43)

Keep the 64 MiB native in-memory read limit. Use an independently installed,
user-imported WitchyBND process only to split oversized DCX/BND containers into a
source-hash/tool-configuration-bound local cache outside game/Mod roots. The cache
publishes only complete validated entry manifests. Bridge parses extracted native
leaves and preserves original container/entry/version provenance. This is the
limited production-authority exception for container transport, not a second
leaf parser. No WitchyBND code or binary is redistributed by SoulForge.

Unpacking does not authorize repacking or Mod writes. Oversized repack remains
unsupported until a separate issue designs verified repack and Patch Engine
writeback. License, configuration, platform, cancellation and verification details
are documented in [Bridge read cache](bridge-read-cache.md).

## Verification limits retained from retired governance records

These are historical coverage limits and owner decisions, not a replacement scope registry or a claim that this refactor ran the omitted checks. Current source contracts and actual per-leg results determine present capability. In particular, the old FLVER/MSB no-write and TAE/ESD version restrictions are superseded where the current native writer and editor contracts provide the implemented paths.

- The target corpus was Sekiro 1.6.x. Version-family approval, private locators and historical fixtures never proved every build or variant. DFLT's historical 144 samples/two layouts, DFLT-BND4 evidence and private KRAK decompression previews do not establish unknown flags/layouts, KRAK recompression/write/recovery or complete release coverage. Oodle remains user supplied and subject to runtime/license validation; it is not redistributed. Unknown bytes/layouts are preserved or rejected by the native writer.
- Workspace authority stays with one writable Mod overlay and an optional read-only game base. Application metadata is external to the Mod. Scope approval never proved every writer had its staging, revision conflict, backup, independent readback, operation/file/resource audit and recovery failure paths exercised. Original game files are not write targets; missing native recovery coverage remains a real verification limit.
- FMG's private 18/18 examples were not proof of all official languages, cross-container references or game loading. PARAM's historical first-party package had 160 definitions; gameparam coverage did not cover drawparam/gparam, unknown layouts or every native writer/load case. The latter two containers were deferred from the V0.5 commitment, not reported completed. First-party schema provenance/digest checks do not confer native format authority. Historical Smithbox imports/adapters were development evidence, not a production dependency or redistribution permission.
- EMEVD's historical first-party package covered 405 instructions in 27 banks. Uncovered instructions and mismatched lengths remained opaque/read-only; a DSL must pass its typed compiler and Patch Engine path rather than write binary directly. Typed equal-length mutations, control-flow checks and corpus roundtrips do not imply full instruction semantics, every layer/KRAK variant or game loading. No third-party EMEDF runtime authority is inferred.
- Registered MSB scene/typed-mutation and FLVER/TPF roundtrip examples established only the variants and operations tested. They did not prove full streaming, all entity/layout variants, KRAK combinations, material/reference semantics or game loading. FLVER authority had previously been overstated because tangent/bitangent/vertex-color, duplicate vertex semantics and material/GX fields were not reported as unparsed gaps; byte-identical roundtrip does not establish parsed semantics. The current `unparsedGaps`/layout diagnostics and per-writer checks remain the boundary. MTD, collision/navigation and native-to-open conversions had unverified or candidate evidence; proxy geometry/graphs, minimal DDS or raw file replacement are not native semantic/conversion proof.
- ACTION/TAE motion identity, same-family ANIBND membership, clip/pose and cross-resource references each need their own validation. Other games, filenames and animation-ID ranges are not substitutes. TAE/ESD writers, unknown-structure reencoding and editor development have no old V0.5/V0.6 version ban; parser coverage does not automatically prove native writer, readback, recovery or game-load authority. ESD's historical scan reported 192 documents, 41,467 transitions and 23,626 command calls with no dangling/sentinel targets; expression/argument RPN bodies were opaque offsets/lengths. Graph closure did not establish their semantics or a verified release editor.
- Script evidence distinguishes LuaP (`\x1bLuaP`, byte 0x50) luabnd bytecode from LuaQ (`\x1bLuaQ`, 0x51) action HKS. Historical source-edit coverage was six plaintext entries: `goal_list.lua`, `543000_battle.lua`, `801000_battle.lua` (in `m25_00_00_00.luabnd`, not aicommon), plus action `eventnameid.txt`, `statenameid.txt`, `variablenameid.txt`. The three name tables use CP932 and preserve their 3/5/14-byte trailing NUL padding. Decoder-derived Shift-JIS encoding roundtripped the tested files; it is not proof against every external CP932 mapping, and unmappable characters must be rejected.
- `801000_battle.lua` had mixed Japanese/GBK comments. ASCII byte replacement preserved all non-ASCII bytes without a whole-file decode/reencode; those comments were not safely editable through that path. The historical file-side 6/6 and production-tool-side 1/1 write/readback/rollback runs are distinct counts and distinct container, loose-file and mixed-byte paths. Magic sampling may leave an individual entry unverified; source editing checks that entry's actual bytes. Printable-ratio 0.99 was a measured discriminator for that corpus, not authority to relax classification on future files.
- That script scan covered the Mod side; twelve game-side KRAK/Oodle luabnds were not read in that run. Bytecode disassembly is not editable source. HKS recompilation, full behavior graph/HKX semantics and bytecode typed mutation were not delivered by plaintext editing. Lua AI action choice and TAE/PARAM animation frames, recovery and damage are separate capabilities. External DSLuaDecompiler/Yapped/DarkScript3 tools were comparison aids only; DarkScript3/SoulsFormats source was not licensed for incorporation.
- The reviewed editor harness covers BND4/FMG/PARAM/EMEVD/script/TAE/ESD; MSB/FLVER retain their independently implemented writes without automatically entering that inventory. Hex/raw remain read-only evidence views and script whole-file replacement is not typed mutation. Demo/synthetic samples, missing native authority/revision, stale revisions, missing full bounded access and premature release-pass claims stay negative cases. The harness remains candidate, with real Electron/document functional acceptance pending. Capacity/latency/benchmark thresholds were not required by the owner decision.
- Default provider configuration is empty; unconfigured services diagnose without a network call. Offline dual-protocol conformance/fake loops do not prove third-party availability, real-model quality or native mutation authority. Real-provider credentials were not a prerequisite for the V0.5 offline acceptance. The historical single permission mode mixed approval and sandbox concepts; any future separation needs its own IPC/permission design rather than a side effect of governance retirement.
- The historical me3 0.12.1 probe/adapter fixtures did not prove actual profile/launch/diagnostics/terminate, Sekiro lifecycle or restart after rollback. The adapter is replaceable; the owner allowed a separately implemented loader while preserving no-write-to-original-game and transaction/audit boundaries. Owner-machine WebGPU/WebGL2 functional rendering checks did not prove representative hardware compatibility, performance budgets or large-map foreground responsiveness.
- NSIS configuration and same-machine builds do not prove installation, upgrade, uninstall, packaged runtime or cross-machine reproducibility. Unsigned releases do not claim publisher/SmartScreen trust; signing, installer size/time and representative hardware budgets were outside the historical acceptance. License notices and redistribution rights still apply to delivered content. The V0.9.1 public prerelease scope did not declare the V0.5/V0.6 work complete; known backend-analysis exit issues, unverified large-map responsiveness and incomplete cross-machine/real-game acceptance remain release-note limits unless later evidence resolves them.
- The V0.9.2 updater/asset/CI implementation did not itself create a tag/Release/upload or prove end-to-end remote updates. Existing V0.9.1 users need one manual bootstrap install; source/non-NSIS builds update manually. Latest metadata, blockmap and SHA256SUMS/asset checks, no draft/downgrade/unapproved destination, main-owned download/token/temp state and renderer-safe status remain actual update boundaries. Cross-machine A→B, real network, stable-channel behavior and SmartScreen/UAC acceptance were still unverified in those records.
