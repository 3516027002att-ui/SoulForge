AI-native Mod engineering workbench

把 Mod 制作，变成一条可解释、可验证、可回滚的产品流程。

SoulForge 面向《只狼》Mod 创作者：用户用自然语言描述目标，Agent 在真实工作区里定位资源、读取原生证据、生成修改计划，并通过 Patch Engine 完成受控写回。

先解决创作者的真实摩擦

传统工作流不是“没有工具”，而是工具之间没有共同的上下文。复杂 Mod 越往后，查找、串联、验证和恢复越依赖个人经验。

现状 01

解包与切换

先解包，再在多个编辑器、脚本工具和查看器之间来回切换；用户目标无法连续传递。

现状 02

隐性知识

即使是参数编辑，也要理解参数组之间的串联、并联和引用关系；新手很难知道下一步应该查什么。

机会 03

AI 原生交互

今天的工具可以理解自然语言、调用工具和生成代码，但 Mod 工作流还缺少安全的领域编排层。

产品闭环

Agent 不是一个“替用户随便改文件”的聊天机器人，而是一个受证据、权限和原生格式边界约束的协作编辑器。

01 / 目标

说清楚想改什么

自然语言目标、当前选区和附件进入同一任务。

02 / 证据

定位资源

检索术语、数字 ID、资源 URI 和引用关系。

03 / 原生读取

确认当前值

读取原生文档，保留 sourceHash 与 sourceRevision。

04 / 方案

生成 Patch

展示影响面、风险和未覆盖的未知字段。

05 / 提交

审批后写回

只经 Patch Engine、staging、备份和原子提交。

06 / 恢复

验证或回滚

写后重读；失败关闭，用户可撤销本次操作。

我做的关键产品判断

真正的 AI 产品能力，不是堆模型名，而是让模型能力、领域数据和风险边界彼此匹配。

检索

lexical 优先

Mod 语料大量包含精确 ID、表名、字段名、符号和路径。首选本地词法 + 结构化 ID + 一跳引用扩展：成本低、结果可解释，也不要求用户有额外 embedding/API 能力。

模型

模型是可替换的推理层

开发阶段按任务混合使用 Opus 5、GPT-5.6 Sol、Luna、Grok 4.5/4.6、GLM 5.3、Flash、DeepSeek V4 Flash、Qwen 3.8 Max；运行时由用户自行配置 API，按成本、性能、延迟和任务复杂度选择。

安全

权限和证据先于执行

只读发现、原生读取、提案、验证、变更和回滚分级；写操作需要审批，失败或证据不足时明确拒绝，不靠模型“自信”推进。

用户：把鬼刑部从 BOSS 改成精英怪，增加一个靛蓝星陨，红点数改为 2
Agent → workspace_stats       获取当前工作区索引范围
Agent → retrieve_evidence    lexical / ID / 引用关系定位候选
Agent → read_param_fields    原生读取当前值与 sourceHash
Agent → build_patch_graph    汇总跨参数与文本影响面
Agent → validate_patch       检查字段类型、范围和前置条件
Agent → approval-requested  展示改动摘要，等待用户确认
结果：工具调用、失败原因、审批决定和会话历史均可回看

不是概念图，是可回看的实践

仓库保留了 Agent 的多轮任务记录；作品展示以实际会话轨迹、代码能力和可复核边界为证据，不用虚构业务指标。

真实任务

复杂参数修改

已有会话归档包含“鬼刑部”相关修改请求，最长记录 64 步。可从中展示发现失败、换路径定位、证据累积和多轮收敛。

可观察

每一步都能解释

任务面板显示模型服务、步骤、工具调用、重试、上下文压缩、审批和会话记录；错误参数不会被静默隐藏。

可验证

结果不等于模型输出

候选发现不能直接写入；原生读取、Patch 校验、用户审批、写后重读和回滚分别承担不同责任。

作品里展示证据来源不会声称
Agent 能理解领域任务并调用工具代码中的工具注册、任务循环和本地会话归档不会把一次成功对话包装成全格式 native 完成
模型服务可配置桌面端模型服务设置与加密凭据通道不会声称所有列出的模型都已真实联网验证
安全写回闭环Patch Engine、审批、验证、备份和回滚接口不会把 synthetic/partial 测试写成游戏内完整验收

主动承认边界

产品判断的一部分，是知道什么不应该在当前版本里承诺。

3D 自由操控没有被伪装成已完成能力

当前没有提供像 Blender 那样自由操控 3D 模型和地图的 Agent 接口。原因是这需要额外的场景状态同步、几何/骨骼语义、交互投影和更成熟的模型能力，工作量与技术风险都明显超出本次闭环。现阶段保留结构化地图变换和导入/导出边界，3D 自由操控列为后续方向。
