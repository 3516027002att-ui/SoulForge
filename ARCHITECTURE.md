# SoulForge authority and ownership

- `packages/shared` contains neutral domain/protocol types and logical resource identities
- `packages/agent` contains the independent finite control protocol/kernel and bounded process/event transport. It has no dependency on Electron, renderer, core, native parsers or the workspace index
- `packages/core` owns workspace/domain services, Agent domain adaptation and shared session assembly. ToolRegistry declares permissions, effects and concurrency; bridge projection and CLI guards consume that single declaration
- `apps/desktop` owns trusted UI/IPC, credentials and domain host state. Agent provider/control runs execute in the fixed `agentUtility` utilityProcess; only bounded capability RPC crosses that boundary
- `bridge/SoulForge.Bridge` owns production native format authority. Writers produce controlled staging output, never arbitrary user resource replacements
- Patch Engine owns proposals, locks, source/hash checks, staging, backup, journal, commit, native verification and recovery. Existing journal/operation records remain transaction truth
- The renderer derives session/UI state from events and bounded projections. Resource documents, indexes, semantic scenes and render objects remain different layers

Model output, tool execution, transaction state and independently evaluated task completion are separate facts. Process restart does not authorize replay. Read-only and already-satisfied tasks can pass an applicable independent validator without a write; actual wrong values fail; missing evidence stays unverified.

The desktop public facade is defined in `apps/desktop/src/ipc/publicContract.ts`. `npm run ipc:public:generate` projects its existing named methods into preload and the renderer API type; `ipc:public:check` rejects drift. Renderer DTOs live alongside the contract and have no main-process runtime dependency. Internal IPC handlers do not become public through this catalog. PARAM and MAP registration delegate to application services under `main/services`: session projection, cache ownership and native/transaction orchestration are separate from trusted transport and Electron events. MAP keeps sender/request cancellation ownership in transport and supplies a read signal/terminal observer to the service; bounded character paging has its own instance-owned projection cache. The host supplies verified roots, transaction ports, dialog selection and lazy request-bound confirmation; core and Bridge keep their native/write authority.

Desktop and CLI use the independent finite kernel through the shared session assembly. Core owns option normalization, native/tool-session construction and workspace-bound context/RAG orchestration; hosts supply their platform and storage capabilities with explicit defaults. The old loop is retired from production. Controlled experiments materialize only an explicitly selected, hash-bound legacy snapshot; unavailable historical source remains unavailable. Real-provider quality/cost acceptance and every prior OOM root cause still require their own evidence. Domain registration is being migrated without rewriting established readers, writers or PatchIR.

Checks are executable risk-specific tests. `scripts/check.mjs` discovers root/workspace `test*` aliases, `bridge:verify:*` aliases, `*.test.ts`, `*.test.mjs`, `*.fixture.mjs`, `verify-*fixtures.mjs`, and core `run*Smoke.ts` sources. A failed aggregate does not suppress separately runnable tail checks. Source/name phases (e2e, release and runner fixtures) precede ambient dependency labels; remaining checks follow private native corpus, synthetic Bridge use, then unit. They require no manual registry row. `--require-suite` adds that exact suite to the execution plan, including outside the selected phases; missing or explicitly excluded required suites remain visible failures.

Builds, artifact generators, exploratory probes and paid provider runs remain explicit operations. Registration findings and manual claim/seal/freshness data cannot prohibit an independently runnable product check. Historical release/deferral compatibility data and the old baseline table remain for still-unmigrated consumers; neither participates in active discovery/execution. See `docs/DECISIONS.md` and `docs/AGENT_RUNTIME.md`.

Generic resource preview/search, container/text mutations and Script source compilation/writeback have separate application services. The resource adapter binds trusted events to deferred confirmation requests, while services receive only logical operation arguments and explicit live workspace, transaction, staging and cache ports. Script native-entry hashes, dialect compilation, bounded frames and caller-owned postcommit refresh retain the established paths.

ACTION registration delegates through explicit application ports. `actionService` owns TAE reads, native binder membership projection and the revision/child/session motion cache; `characterPreviewService` owns companion lookup and the shared character assembly helpers used by MAP. Services receive live workspace/index getters without channel registration or sender authority. Core and Bridge retain physical entry identities, hash checks, native parsing and all writer permissions.

Native asset reads and mutations have separate application services under `main/services`. Their trusted adapter supplies live workspace/index ports and lazy request-bound write confirmation. Native writer candidates keep the existing staged output, writable-root, physical/aggregate hash and Patch Engine commit checks; the service receives no Electron event or registrar capability.

The desktop root binds native commit ports through `sessionCommitService`. It retains the original session, operation log, controlled Patch Engine replacement and caller/port refresh ownership. Port-owned projection checks session object and activation generation after commit, preserving the durable receipt when the active workspace has changed.

TEXT/FMG uses an application service for complete document/reference caches, native catalog/table reads and mutation staging. Its neutral read-lifetime entry preserves session capture, reset epochs, delayed-result refusal and cache protection for direct calls as well as IPC. Trusted transport retains the five explicit channels and exposes only the existing logical bounded renderer projections.

RAW resource/container/Script reads use `rawResourceService` below the thirteen trusted channels. It owns the existing enumeration and classification caches, bounded source reads, physical entry/hash binding, native HKS delegation and domain reset. Direct calls enter the same captured read lifetime as IPC; known native function aliases keep service method names distinct from core authority.

EVENT uses an independently callable application service with instance-owned authoritative documents, schema/disassembly caches, window open slots and source tokens. The trusted adapter supplies window identities and lazy confirmation, retaining all seven channel contracts and existing workspace/window lifecycle entry points. Read cancellation cannot publish old workspace data; settled writes keep their transaction facts while old cache/index/knowledge projections are discarded. Native outer-resource hashes, fresh DSL reads and Patch Engine staging remain in core/Bridge.

The desktop root supplies utility process construction, userData/storage selection and reporting ports to `workspaceUtilityLifecycleService`. The service owns operation-log startup serialization, recovery cleanup admission, read-only knowledge snapshots, retry cooldown and disposal tokens. Store references are live read-only getters; immutable host port capture prevents pending work from adopting replaced adapters.

Semantic/RAG refresh scheduling and postcommit scan, scoped analysis, native decode, source-delta persistence and projection are owned by `semanticRefreshService`. The root supplies live session, activation generation, catalog revision, index, corpus and utility ports. Queued native-read batches and awaited candidates retain their original owner; durable publication rejects replacement and ABA results. Existing Agent idle coalescing, 180-second postcommit deadline, caller/port refresh ownership and committed transaction facts remain. Workspace scan/canonical-PARAM lookup uses its existing separate projection strategy.

Workspace lifecycle, file/fingerprint indexing, ACTION membership, readiness and RAG publication are owned by `workspaceService`. The trusted workspace adapter retains sender-bound, expiring, one-shot directory credentials, dialogs and remembered directory selection; application calls receive only admitted directories through lazy callbacks at the original admission points. Storage and utility/cache capabilities are explicit immutable host ports. Existing workspace state getters remain compatibility exports for other domain hosts. `workspaceRuntimeService` delegates ME3 detect/profile/launch/terminate to core with the existing version policy and deadlines; process gateway construction remains a desktop host port.

Opaque editor-document operations use `documentService` for locator probing, the existing core store, revision/owner checks and logical result projection. The six trusted document channels derive window/session owner scopes in transport and supply a lazy main-derived owner callback after the original request decoding. Direct service reads enter the same captured workspace lifetime and reset epoch as IPC. Host functions are captured immutably while session/index getters remain live; native stage-root admission and the fixed probe budget are retained. Unconnected document readers/writers continue to return their existing capability/refusal outcomes.

Operation history and rollback orchestration use `operationService` below the three trusted operation channels. The adapter binds each request's trusted event to a lazy neutral confirmation port. History filtering/logical path projection, native rollback admission, dedupe cleanup, original transaction inputs and result carrier identity are retained; core and Patch Engine continue to own inverse transactions, source/hash verification, backup and journal truth. Host functions are captured immutably and current session/log/file getters remain live. This boundary extraction alone does not establish late-owner or postcommit projection safety.

Agent run/session/approval/replay coordination uses `agentSessionService`; local embedding and source-bound evidence retrieval use `agentEvidenceService`. Trusted transport retains sender/grant/reference admission, provider credentials/configuration/usage authority, native confirmation dialogs and window event targets. A session receives only an admitted owner/mode and a request-bound execution capability over the existing shared assembly and utility runner. Event retention, approval timeout, run budgets, native proof ownership and late host-operation settlement keep their established contracts. Each admitted window binds its own publish/destroy lifetime; local embedding refuses replaced workspace or corpus results.

Operation requests capture the entry session object, activation generation, original operation log and minimal source-label primitives before awaiting. Lookup/confirmation cannot rebind a rollback to another owner. Dedupe keys separate session identity and activation epoch; inverse transactions already in flight retain their original receipt and skip another workspace's projection. Failed postcommit refresh adds a masked warning while preserving op/inverse identity and the original result carrier. Delayed history reads refuse a changed owner; none of these rules replay transactions.
