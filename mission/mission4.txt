一、ACTION：先修真实运行时 frame-size blocker

当前真实 Electron UI 已经直接出现错误：

Bridge result exceeds the negotiated frame-size limit; use a file-backed command instead.

ACTION 预览表现为：

但动作不播放
预览区域直接报告上述 Bridge frame-size 错误

这条错误是当前最高价值运行时证据。

不要首先继续猜 HKX 不存在。

不要首先继续改 motion binder ID。

不要首先继续改 duplicate bone mapping。

先确定：

哪一个 ACTION Bridge command 正在把过大的结果通过普通 framed RPC 返回。

1.3 ACTION 大 payload 改成 file-backed

目标架构：

Bridge 不再把完整大动画数据作为巨大 JSON frame 直接返回。

Bridge 处理动画后，将大 payload 写入受控的临时/缓存文件，只通过正常 RPC 返回一个很小的 descriptor。

descriptor 至少必须能让 Desktop 确定：

result 文件位置或 opaque token
payload format/version
byte length
animation duration
frame/sample count
bone count
resource/source revision 或 hash
必要的诊断信息

不要把文件路径设计成 renderer 可以任意读取的安全漏洞。

如果项目已有 opaque file token / file-backed result authority，复用它。

如果实际 ACTION 只需要当前时间点 pose，而不是完整动画所有帧，优先检查是否应该根本不返回完整 clip。

例如播放期间若可以：

timeSeconds → Bridge/native sample → 一帧 compact pose

就不要预先把：

N bones × N frames × transforms

全部 JSON 化送到 renderer。

但不要未经 profiling 就擅自重写整个动画体系。

先确定当前 command 实际返回内容和 renderer 实际消费内容。

1.4 大量浮点数据禁止继续展开成巨大 JSON object graph

如果当前 payload 类似：

frames[].bones[].translation.x

frames[].bones[].rotation.x

这种对象树，必须评估并优先改成紧凑 binary layout。

优先：

float32

连续数组

固定 header

TypedArray / ArrayBuffer 可直接消费的数据布局

不要为了“可读性”把几百万个 float 继续 JSON 化。

元数据可以 JSON。

大量 geometry / animation 数值不应使用巨大 JSON。

二、ACTION：修复已确认的 motion identity cache 污染

当前源码审计已经发现确定逻辑错误。

搜索：

taeMotionIdentityCache

检查当前 key。

如果仍然只是：

sourceUri

而缓存值是某一个具体 animId 对应的 motionAnimId：

这是错误的。

因为同一个 TAE source 可以包含多个动画。

第一次读取：

sourceUri + animId A

得到：

motionAnimId X

如果 cache 只按 sourceUri：

第二次读取：

sourceUri + animId B

可能错误复用 X。

这会造成同一 TAE 内不同动作互相污染。

2.1 正确修复

优先方案：

一次解析 TAE 后，缓存：

sourceUri + revision → Map<animId, motionAnimId>

查询时：

map.get(animId)

如果现有结构暂时无法做到文件级 map，则最低限度 key 必须包含：

sourceUri

animId

以及必要 source revision。

禁止继续只按 sourceUri 缓存单个 motion identity。

2.2 必须新增能抓住旧 bug 的回归测试

旧测试如果只测一个动画，不够。

必须在同一个真实或忠实 fixture TAE source 中至少存在两个：

animId A → motionAnimId X

animId B → motionAnimId Y

其中：

A != B

X != Y

测试顺序必须：

第一次查询 A

然后查询 B

然后再次查询 A

断言：

A 始终 X

B 始终 Y

不得因为 cache warmup 导致 B 返回 X。

然后反向：

先 B 再 A。

两种顺序都必须通过。

8.2 强制做一次真实 writable mod overlay 闭环

禁止写 vanilla 游戏文件。

选择一个易于读取的真实资源字段。

PRE

A → B。

8.3 三层结果分别记录

必须明确区分：

disk/native fresh authority
workspace/index/document semantic state
renderer/UI state

如果：

native=A

workspace=A

UI=B

则是 renderer invalidation First Bad。

如果：

native=A

workspace=B

UI=B

则是 index/document invalidation First Bad。

如果：

native=B

rollback 却报告 success

则 rollback/transaction First Bad。

如果：

但 fresh native reopen 得到非法/不一致语义

则是 semantic post-commit verification gap。

不要把三种情况混在一起。

如果实际上是两个不同概念：

必须重新命名，使用户不会理解为同一个 boolean。

例如不要同时用：

“未挂载”

“已挂载”

表达：

“当前 workspace 未启用”

和

“目录路径有效”。

如果它们理论上应该是同一个状态：

统一到一个 authoritative selector/state。

禁止两个组件各自推导。

这一项交给前端 Agent实现，但主 Agent应提供实际 backend state 语义。

十四、不要把 governance / capability flag 当完成功能证据

如果 capability contract 里出现：

releaseWriteEnabled: true

deferredPreview: null

之类声明：

它不能证明功能已经真实可用。

真实 Electron：

动作不播放

Bridge 报 frame limit

就说明 runtime contract 还没满足。

不要因为某个 capability JSON 说 release-ready 就跳过真实验收。

测试必须证明行为，不是证明 flag。

十五、测试要求：必须堵死常见假绿路径

ACTION 不能只测：

一个 animId

一个 synthetic binder

一个 mock Bridge result。

必须至少证明：

同一 TAE 两个动作

不同 motionAnimId

不同 binder entry

正确 container

真实 HKX

真实 pose change

Electron 播放。

PARAM 不能只测：

返回 500 rows。

必须证明：

首屏前没有 decode 全部 rows。

ROLLBACK 不能只测：

transaction 返回 success

history cursor 更新

按钮 enable 状态改变。

必须证明：

fresh native authority A→B→A

workspace A→B→A

UI A→B→A。

MAP 不能只测：

Bridge 返回 non-empty geometry。

必须证明：

Electron scene 中 proxy cube 被真实 geometry 替换。

如果由于环境条件暂时无法跑 Electron：

明确写：

NOT VERIFIED

不能写：

PASS

不能用 unit smoke 代替 Electron PASS。

十六、施工顺序固定，不要自行重排

按以下顺序执行：

定位 ACTION frame-size 实际超限 command。
把 ACTION 大 payload 接入已有 file-backed transport。
修 taeMotionIdentityCache cache identity。
跑双动作真实 ACTION resolver 验证。
完成真实 Electron 动作播放。
如果之后 duplicate bone mapping 才真正成为 blocker，再做 hierarchy identity。
对 PARAM 做 cold-open profiling。
消除 session open 前不必要的 full parse / full roundtrip 阻塞。
做 PARAM 真 lazy row decode 验证。
做 ROLLBACK overlay A→B→A 三层 authority 闭环。
仅根据闭环结果修 transaction 或 invalidation。
追 MAP readMapPartMesh → renderer 链。
证明 MAP 是否也存在大 payload frame blocker。
后端将 MAP renderer 结果和 transform contract 交给前端 Agent。
前端再完成 Universal Transform Gizmo、proxy replacement 和设置状态文案一致性。

不要同时在四个系统里大面积重构。

每解决一个 First Bad 就重新跑真实链。

不要因为“后面肯定还有问题”一次性把所有代码重写。

十七、每完成一个阶段必须留下证据

不要只回复：

“已修复。”

实际 First Bad

为什么旧逻辑错

真实测试数据

关键运行结果

仍未验证的部分。

十八、最终禁止事项

不要：

修改 ACTION 的 1e9 + motionAnimId 规则。

不要：

给 c0000 animation container 写特判。

不要：

根据 aXXX 文件名范围猜动作。

不要：

随机 sibling 扫描并取第一个。

不要：

duplicate bone 直接取第一个。

不要：

用提高 Bridge frame limit 掩盖大 payload 架构问题。

不要：

不要：

新增第三套 PARAM API。

不要：

在没有新 native 证据时重新修改 MAP FaceSet 修复。

不要：

因为 rollback UI 按钮发生变化就判定 rollback 成功。

不要：

用 capability flag / smoke test 宣布 Electron 功能完成。

不要：

为了让测试通过减少真实断言。

给前端 Agent 的独立施工任务如下。

它只处理已经明确属于 renderer/UI 的问题，不重新研究 ACTION native parser、PARAM parser 或 rollback transaction engine。

首先处理 MAP Universal Transform。

搜索：

移动

旋转

缩放

以及当前 transform mode / gizmo component。

删除主界面三个互斥的移动、旋转、缩放模式按钮。

默认选中地图对象时直接启用 Universal Transform Gizmo。

同一个 gizmo 同时提供 translation、rotation、scale handle。

拖动 translation handle 时只能修改 position。

拖动 rotation handle 时只能修改 rotation。

拖动 scale handle 时只能修改 scale。

继续复用现有 transaction/write pipeline。

禁止因为 UI 合并而绕开正式 transaction engine。

一次完整 drag gesture 应形成合理的单次 edit/transaction，不要 pointermove 每一帧制造几十条独立历史记录。

如果已有 drag begin/update/end 生命周期：

复用它。

快捷键 G/R/S 可以继续作为效率模式，但不要再让三个按钮成为默认主要入口。

其次处理 MAP proxy replacement。

后端 Agent会提供：

某个真实 part 的 mesh resolve 结果

Bridge/file-backed delivery 情况

renderer 实际收到的数据。

如果 renderer 已经收到有效 mesh：

追踪 proxy entity 和真实 geometry entity 的生命周期。

真实 mesh ready 后：

必须 atomically 替换 proxy。

不得：

真实 mesh 和 cube 重叠存在

mesh 成功但 cube 不移除

切换地图后旧 mesh 泄漏

资源 reload 后继续显示旧 proxy。

加载过程中可以显示 proxy。

真实 geometry READY 后必须消失。

真实 geometry FAILED 时可以保留 proxy，但必须有明确 diagnostic reason。

禁止把所有失败静默表现成一个方块，让用户无法知道：

resource missing

parse failed

transport failed

renderer failed

分别是哪一种。

然后处理 rollback UI readback。

后端完成 rollback 后如果 authority 已经恢复：

前端必须 invalidate/reopen 当前受影响 editor。

如果当前资源就是 rollback target：

刷新 document。

如果当前资源不受影响：

不要全局把所有 editor 都重载。

不得只刷新 history panel。

必须保证用户看到的字段恢复。

Undo/redo button enabled 状态必须来自真实 history authority，而不是局部临时 optimistic state。

transaction 失败时：

不得提前移动 history cursor。

不得先闪按钮再悄悄失败。

最后修设置页矛盾：

“原版游戏目录”

下面的“未挂载”

和右侧绿色“已挂载”

不能同时出现。

workspace mounted

就把文字改成两个明确不同概念，例如：

“目录已配置”

“尚未载入工作区”

不能继续都叫“挂载”。

如果它们其实应该表示同一状态：

使用单一 authoritative state。

不要在两个 React component 中分别推导。

前端验收必须使用真实应用操作，而不是 snapshot test：

打开 Settings：

同一目录状态不得出现逻辑矛盾。

打开 MAP：

直接能从同一 Gizmo：

每种操作提交后重新读取 entity transform，数值正确。

关闭地图重新打开：
