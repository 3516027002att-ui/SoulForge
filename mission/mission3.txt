# MAP FaceSet 选择规则的决策边界

修改时必须保持一个原则：

**一个 mesh 最终只选择一个 display FaceSet 作为当前 V1 projection。**

不要合并全部 LOD。

不要把多个 FaceSet 的 triangle list 拼接起来。

原因是多个 FaceSet 很可能代表不同显示层级或特殊 rendering purpose；直接拼接会制造重复表面、Z fighting、错误 LOD 或特殊 pass 被当普通 geometry。

当前 V1 的目标只是从真实 Sekiro FLVER 中确定一个稳定的普通 display projection。

同时保持：

* triangle strip → triangle list 的现有展开逻辑
* primitive restart 逻辑
* winding 逻辑
* IndexSize 保护
* EdgeCompressed fail-closed，除非真实证据和现有 parser 能力已经证明可以解析
* maxIndices / allowTruncation 当前契约
* `GetMeshIndexSize` 与 `GetMeshIndicesBase64` 必须选择**同一个 FaceSet**

禁止让这两个函数各自复制一份不同的 candidate 筛选逻辑。

如果当前代码中这两个函数已经各自实现一遍：

`FaceSet candidates → displayCandidates → selected`

则本次修复时把“选择哪个 FaceSet”的纯语义提取成一个**私有 helper**，两个函数共用。

helper 只负责：

`给定 meshIndex / mesh → 返回被选中的 FlverFaceSetEntry（以及需要时的引用 ordinal/index）`

不要把 index 解码、triangle strip 展开等一起塞进去。

不要创建新的公共 API。

不要创建新的 service。

不要移动 `FlverNativeDocument` 的职责边界。

helper 名称以当前项目风格为准，例如语义应明确表达：

`SelectDisplayFaceSet...`

而不是模糊的：

`GetBestFaceSet`

因为这里不是评分算法。

在真实诊断结果出来后严格按下面分支执行：

如果原 19 个失败模型中：

* 没有 `Flags==0`
* 第一个 referenced FaceSet 全部属于当前可解析的普通非 EdgeCompressed FaceSet
* IndexSize 都是当前支持的 16 或 32
* 没有未知、会改变 index 编码的特殊 flag

那么采用最小兼容规则：

1. 如果 referenced candidates 中存在 `Flags==0`，按 reference order 选择第一个 `Flags==0`。
2. 如果不存在 `Flags==0`，按 reference order 选择第一个当前 parser 明确能够解码的非 EdgeCompressed FaceSet。
3. 如果第一个候选不支持，但后面存在普通可支持候选，不要静默跳过未知语义直到找到一个“能画”的；这种情况停止修改并记录实际 flags，因为这意味着选择优先级需要额外语义证据。
4. 如果 candidates 中只有 EdgeCompressed 或当前不支持的 index representation，则保持 fail-closed。
5. 不得因为多个 `Flags==0` 就整 mesh 失败。多个 `Flags==0` 时按 reference order 取第一个，并通过 regression test 固定其确定性。

这里之所以允许“多个 Flags==0 取第一个”，不是因为当前 19 个样本出现过它，而是当前实现的“恰好一个”限制本身没有 FLVER mesh reference order 语义上的必要性；选择必须确定且单值，reference order 已经提供确定顺序。

但是，如果运行时 diagnostic 显示：

* 首位 FaceSet 经常是 EdgeCompressed
* 或首位有未知 flags
* 或不同失败 mesh 的 flags 分布存在明显不同类别

不要继续套上述 fallback。

此时必须保留 diagnostic，并在工作记录中列出真实 flags 分布；不要凭猜测完成 MAP 产品修改。

在这种情况下，本任务允许 MAP 暂时停在“证据已补齐、实现等待明确语义”的状态，绝对不允许为了完成任务而扩大兼容声明。

`mesh.FaceSetIndices`

不得对 FaceSet 按：

* Flags
* IndexCount
* triangle 数量
* 文件全局 FaceSet index
* “看起来更完整”
* “面积更大”
* “顶点更多”

重新排序。

reference order 是默认确定性顺序。

如果 runtime diagnostic 已证明原 19 个失败模型符合“首个 referenced FaceSet 是当前 parser 可以完整解码的普通 FaceSet”这一条件，则 selection 规则实现为：

1. 建立当前 mesh 的 referenced FaceSet candidates。
2. 如果 candidates 为空，保持当前空/失败行为，不伪造 geometry。
3. 如果存在 `Flags == 0` 的 candidate：

   * 选择 reference order 中第一个 `Flags == 0`。
4. 如果一个 `Flags == 0` 都不存在：

   * 检查 reference order 中第一个 FaceSet。
   * 只有它满足当前实现已经支持的 index representation，且不是 EdgeCompressed，且 diagnostic 没有发现其包含当前 parser 不理解的会改变 index 数据语义的 flag 时，才选择它。
5. 如果第一项不能被当前 parser可靠解释：

   * fail closed。
   * 不向后扫描寻找一个“碰巧能画”的 FaceSet。
6. 多个 `Flags == 0`：

   * 不再因为数量大于 1 而失败。
   * 只取 reference order 中第一个。
7. 任何情况下只返回一个 selection。
8. selection helper 不得吞异常。
9. selection helper 不得进行 triangle strip 展开。
10. selection helper 不得改变 `IndexSize`。
11. selection helper 不得截断 index。
12. selection helper 不得自动过滤坏 triangle。
13. selection helper 不得执行 geometry repair。

如果你无法从实际 Flags 分布证明“非零 flag 不影响当前 index projection”，不要以“SoulsFormats 好像能画”为理由扩大支持。

这次修复的 authority 是：

**SoulForge parser 实际解析出的真实 Sekiro 文件 + 成熟工具语义作为对照。**

成熟工具只能帮助解释。

# 防止“测试假绿”

下面任何一种情况都不能写 PASS：

1. 测试命令 exit 0，但真实 corpus harness 没跑。
2. harness 只跑了修复后新挑的成功样本。
3. 原失败样本被从 sample list 删除。
4. 原 healthy model 回归，但总成功数量增加。
5. ACTION 从 0/40 变成若干成功，但成功的是和修复前不同的 sample set。
6. clip 返回成功，但 pose 恒等于 reference pose。
7. MAP 返回 success，但 chunkCount=0。
8. MAP 返回 chunk，但 triangleCount=0。
9. renderer 初始 proxy 被误认为最终 geometry。
10. UI session 没挂 vanilla base，却把模型 missing 判成 renderer bug。
11. test 被 skip，却写成 PASS。
12. 修改 test expectation 使原错误行为成为“正确答案”。
13. catch 原异常后返回空对象，让上游不报错。
14. 为了让 c0000 动，随机选择另一个 HKX。
15. 为了让地图显示，任意选择一个 binder FLVER 或 FaceSet。
16. 删除 fail-closed 条件但没有真实 corpus proof。

出现以上情况必须恢复正确验证。

# 最终原则

这次任务不是：

“让地图看起来不像方块，让骨骼看起来动一下”。

而是：

**把两个已经运行时确认的 First Bad 用真实 Sekiro 格式语义修掉，并证明修复没有把错误从一层推到下一层。**

始终遵守：

观察到什么，就修什么。

没有证明的下游，不碰。

有歧义，fail closed。

真实 corpus 优先于猜测。

旧健康路径必须回归。

成功必须由 before / after 同样本证明。

UI 症状只能由 UI 路径验证。

不要用测试绿替代真实结果。

不要用“能显示”替代“显示的是正确资源”。

不要用“能动”替代“播放的是正确动画”。
